# Changelog

## [Unreleased]

### Added
- `household-manifest.yaml` state model (ADR-0013, FR-BAK-002): a `state:` map listing each stateful module's volume, mount, env, kind, `personal`, and optional `backup: false`/`shares`/`service`; a `stateless:` list; and `excluded_volumes:` with reasons (library media, key material, backup output).
- `scripts/check-state-coverage.sh` (+ `_test.sh` with good/bad fixtures under `scripts/testdata/state-coverage/`, run by `run-script-tests.sh`). It checks that every required or recommended module is in `state` or `stateless`, and that each state entry's volume, mount, and env match its registry compose service. It also checks that backup-local mounts every backed-up volume read-only at `/source/<module-id>` and lists it in the default `BACKUP_SOURCE_DIRS`, and that excluded volumes are never archived. Drift in optional modules only produces a warning. Requires mikefarah `yq` v4 and `jq`.
- `scripts/check-publish-set.sh` (+ `_test.sh`, run by `run-script-tests.sh`): fails when any image in `docker-compose.registry.yml` (all profiles) is missing from `publish-module-images.sh` `DEFAULT_MODULES` (T-M2-02, TDD section 5). `muxcored` (module `core`) is published by `publish-muxcored-local.sh`.
- `cmd/mediauiprox/routes_inventory_test.go` and a complete `BFF-API.md` "Route inventory" table: the test fails on any registered route missing from the doc or documented but not registered (T-M2-08, TDD section 7).

### Changed
- `docker-compose.registry.yml`: each stateful module now has a named volume mounted at `/data` (the `app` user's home, so it is writable), with its DB/state env pointing into it. Previously the defaults fell into the image filesystem or `/tmp`. Changes: `SQLITE_DB_PATH`, `SECRETS_STORE` (+ `SECRETS_MASTER_KEY` passthrough), `ENCRYPTION_KEY_FILE`, `ADMIN_UI_DATA_DIR`, `MOVIES_DB_PATH`/`MOVIES_IMAGE_DIR`, `TVSHOWS_DB_PATH`/`TVSHOWS_IMAGE_DIR`, `SCANNER_DB_PATH`, `AUTOMATION_DB_PATH`, `REQUEST_DATA_DIR`, `FORMATS_DB_PATH`, `RENAME_DB_PATH`, `FFPROBE_DB_PATH`, `SUBS_DB_PATH`/`SUBS_DIR`, `ROOTS_DB_PATH`, `MEDIA_UI_USERDATA_DIR`. New volumes: `secrets-file-data`, `encryption-aesgcm-data`, `admin-ui-data`, `media-{movies,tvshows,scanner,automation,custom-formats,rename,ffprobe,subtitles,root-folders}-data`, `request-media-data`. Existing volume names are unchanged.
- `docker-compose.registry.yml` backup-local mounts every backed-up state volume read-only at `/source/<module-id>` (renamed from `/source/auth`, `/source/sqlite`, `/source/userdata`), and its default `BACKUP_SOURCE_DIRS` lists all of them. The encryption keyring, library media, and downloads are excluded.
- `docker-compose.registry.yml` media-ui BFF wiring: explicit `MOVIES_/TVSHOWS_GRPC_CLIENT_ADDR`, `MOVIES_HTTP_URL`, `TVSHOWS_HTTP_URL`, `REQUEST_MEDIA_HTTP_URL`, `ROOTS_/RENAME_/FFPROBE_/SUBTITLES_GRPC_CLIENT_ADDR`, and `METADATA_TMDB_GRPC_ADDR` using container DNS names, with `depends_on` on movies, tvshows, and request-media. media-movies and media-tvshows mount the `movies`/`shows` library read-only at the scanner's paths so `/stream` can open files. Other wiring changes: `MOVIES_GRPC_ADDR=media-movies:9420` (insecure mode rewrites `:port` binds to loopback), `MOVIES_HTTP_ADDR`/`TVSHOWS_*_ADDR` set explicitly, request-media `REQUEST_HTTP_ADDR` changed from `127.0.0.1:9380` (unreachable from the BFF) to `:9380` (not published) plus `REQUEST_GRPC_ADDR=request-media:9481`, and media-rename `RENAME_GRPC_ADDR=:9510` to match `PORTS.md` and the BFF default.
- `.env.example` and `docs/PUBLIC-INSTALL.md` document `SECRETS_MASTER_KEY` (required for the registry install; keep it outside backups) and the state/backup model.
- `publish-module-images.sh` default publish set now covers every compose profile: added auth-oidc, backup-local, cache-local, downloader-debrid, downloader-native-torrent, downloader-native-usenet, downloader-qbittorrent, downloader-sabnzbd, emby, indexer-piratebay, indexer-torznab, media-dlna, media-intro-outro, media-tagging, media-transcoder-pool, playback-guard, playback-monitor, plex, secrets-vault.
- `mediauiprox`: route registration extracted from `main` into `(*server).registerRoutes` (no behaviour change).
- Pin all install paths to release train `train-2026.10.1` (T-M2-04, FR-INS-006): core / image tag `v0.6.6` in `docker-compose.registry.yml` defaults, `household-manifest.yaml` `core_tag`, Helm `coreTag` + image strings, kustomize base/overlay images, publish/smoke scripts and install docs.
- `scripts/bump-core-pins.sh` now also updates Helm values, kustomize image pins, `local-registry.sh` and the doc pin text, so one run keeps every pin in agreement.

### Fixed
- `mediauiprox` panicked at startup on two `net/http` ServeMux pattern conflicts: `/api/tv/login` (now `POST /api/tv/login`) vs `PATCH /api/tv/{id}`, and `GET /api/music/tracks/` (now `GET /api/music/tracks/{id}/lyrics`) vs `GET /api/music/{id}/history`.
