# Changelog

## [Unreleased]

### Security
- Household security profile for the registry compose (T-M3-02g, ADR-0016 phase 1, ADR-0017): `docker-compose.registry.yml` runs core with `MUXCORE_PROFILE=household` and no insecure flag anywhere. Core's CA lives on a `core-ca` volume (`MUXCORE_GRPC_CA_CERT_DIR`; the core v0.6.15 image owns the mount point), its public `ca.crt` is exported to a `mesh-ca` volume (`MUXCORE_CA_EXPORT_DIR`) that every module mounts read-only at `/data/mesh-ca` (`MUXCORE_TLS_CA`), and core's certificate carries the `core` service name (`MUXCORE_TLS_SERVER_SANS`). Every module service gets a required `MUXCORE_BOOTSTRAP_TOKEN=${MUXCORE_ENROLL_TOKEN_<ID>:?…}`, its own `<service>-id` volume at `/data/mesh-id` (`MUXCORE_TLS_DIR`) and `MUXCORE_ENROLL_DNS_NAMES=<service>`; `jellyfin-bridge`/`plex-bridge`/`emby-bridge` also carry their module ID as a network alias and are allowed by `MUXCORE_ENROLL_SAN_ALLOW`. `MUXCORE_ENROLL_SECRET` is required. Core's HTTP port is HTTPS (healthcheck uses the exported CA). The C-18 workaround is gone: `auth-local`, `call-policy-default` and `publish-policy-default` run in their own containers again (auth-local publishes 9403/9401 itself) and core dials them over CN-checked TLS. The identity volumes are key material in `household-manifest.yaml` `excluded_volumes` (never archived, untouched by a restore). The module/BFF images pre-create `/data/mesh-id` (0700) and `/data/mesh-ca`.
- `scripts/gen-enrollment.sh` (+ `_test.sh`): writes `MUXCORE_ENROLL_SECRET` (random, kept on reruns; `--rotate`) and `MUXCORE_ENROLL_TOKEN_<ID>` for every `MUXCORE_MODULE_ID` of the compose file into `.env` (0600) in a managed block; byte-identical on rerun. Tokens are `mct_2_<id>_` + hex(HMAC-SHA256(secret, id)) — the test compares with fixtures from core's `muxcored enroll token` and with openssl. `--print-token <id>` prints one token.
- `docker-compose.dev.yml`: the insecure dev override (`MUXCORE_PROFILE=dev`, `MUXCORE_INSECURE_DISABLE_TLS=true` for core and every module; security sidecars back in core's network namespace as the dev profile requires). The only compose file allowed to set the insecure flag. `run-host.sh` stays dev.
- `scripts/check-compose-security_test.sh`: the registry compose has no insecure flags or `network_mode: service:core`, core defaults to household with a required enrollment secret, the CA export volume and its service name in the server SANs; every module service has the household profile, its own token variable, its own identity volume, the CA read-only and its service name as DNS SAN (plus the alias/SAN allow-list rule); fixture acquisition defaults are present; the dev override sets dev + insecure for every service. Includes 13 negative fixtures.
- Registry smoke in the household profile: the smoke enrolls a client identity of its own (`mvp-smoke`, `MUXCORE_SMOKE_ID_DIR`, default `run/smoke-id/`) via `BootstrapRegister` with an openssl CSR, then runs grpcurl with `-cacert`/`-cert`/`-key` (TLS auto-detected from the running core; `MUXCORE_SMOKE_TLS=0|1` forces) and checks core health over HTTPS. `proto/smoke.protoset` adds `muxcore.module.v1.ModuleRegistration`. `MUXCORE_COMPOSE_EXTRA_FILES` layers override files (e.g. the dev override) for the smoke and the restore drill.
- `mediauiprox` obtains its mesh identity at startup with `sdk/go/module/meshid.Ensure` (module ID `media-ui`) before any gRPC dial; failure is fatal in household. Bumps core v0.6.15, sdk/go/module v0.6.5 and the sibling module requires to their latest tags.
- No default credentials (T-M3-01, NFR-SEC-001, FR-INS-004): removed the `admin-dev-only` admin password, the `household-monitor` `PLAYBACK_MONITOR_HTTP_TOKEN` and the `minioadmin` S3 keys from `run-host.sh`, both compose files, `.env.example`, `setup.sh`, `bootstrap-auth.sh`, `smoke.sh`, the smoke libs, `cmd/acquirefixture`, and the docs/Helm notes. `docker-compose.registry.yml` now **requires** `MVP_ADMIN_PASSWORD` (`${MVP_ADMIN_PASSWORD:?…}`); `PLAYBACK_MONITOR_HTTP_TOKEN` defaults to empty in both compose files (playback-monitor operator/ingest HTTP stays disabled until set). `run-host.sh` generates a random admin password into `data/auth/admin.password` (0600) when `MVP_ADMIN_PASSWORD` is unset, prints it once on generation (later runs print only the path), and generates `data/playback-monitor/http.token` for playback-monitor and the BFF; storage-overlay now requires `S3_ACCESS_KEY`/`S3_SECRET_KEY`. `setup.sh` generates a random admin password (when left empty) and the health/playback monitor tokens into `.env`. `smoke.sh`, `bootstrap-auth.sh`, the registry smoke and `acquirefixture` read `MVP_ADMIN_PASSWORD` or that file and fail with guidance when neither exists. Upgrade note: an existing auth DB keeps its old password; set `MVP_ADMIN_PASSWORD` to it. Enforced by the umbrella `scripts/check-default-creds.sh`.
- `mediauiprox` CSRF protection (T-M3-04, NFR-SEC-004): `POST`/`PUT`/`PATCH`/`DELETE` must carry an `Origin` (fallback `Referer`) matching `MEDIA_UI_PUBLIC_URL` or `MEDIA_UI_ALLOWED_ORIGINS` (the request's own origin when neither is set); cookie-authenticated requests without either header are rejected with `403 csrf.rejected`. Bearer-authenticated clients that send no `session` cookie (TV/mobile/CLI) are exempt. The session cookie stays `HttpOnly` + `SameSite=Lax` (+ `Secure` on https).
- `mediauiprox` logout is `POST /logout` (CSRF-checked; also revokes a bearer session). `GET /logout` now only renders a confirm page whose form POSTs, so a cross-site link can no longer end a session.
- `mediauiprox` serves through an `http.Server` with `ReadHeaderTimeout` 10s, `ReadTimeout`/`WriteTimeout` 2m and `IdleTimeout` 2m (NFR-SEC-006); `/stream/*`, `/api/sessions/events` and `/api/debrid/stream` lift the deadlines per request with `http.ResponseController`. Every response sets a CSP for the SPA (override `MEDIA_UI_CSP`), `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff` and `Referrer-Policy: strict-origin-when-cross-origin`.
- `mediauiprox` sessions persist across restarts (NFR-REL-003) in `MEDIA_UI_USERDATA_DIR/sessions.json` (0600, dir 0700), keyed by SHA-256 of the session token, with the auth-local token AES-256-GCM sealed (`MEDIA_UI_SESSION_KEY` or a generated 0600 `session.key`), following admin-ui v0.1.15. Expired or undecryptable entries are dropped on load.
- End-user identity propagation (T-M3-06b, ADR-0019, NFR-SEC-007): the request-media proxy no longer copies client `Cookie`, `Authorization`, `X-Caller-Id`, `X-MuxCore-*`, `X-Tenant-ID`, `X-Auth-Claims-Tenant`, `X-User-ID` or `X-Auth-Token`; it sends `Authorization: Bearer <auth-local token>` for the signed-in user and, for one release, `X-Caller-Id=<user id>` (`X-MuxCore-User` / `X-MuxCore-Roles` are no longer sent). The userdata-local proxy and the Jellyfin `/userdata/from-muxcore` push (jellyfin v0.3.2+ requires it) send the bearer plus `X-MuxCore-User-Id` instead of `X-User-ID`/`X-Tenant-ID`. The `/stream/*` and `/images/*` reverse proxies strip the same headers.
- health-monitor HTTP (NFR-SEC-011): `run-host.sh` binds `127.0.0.1:9203` by default and generates a bearer into `data/health-monitor/http.token` (0600) when `HEALTH_MONITOR_HTTP_TOKEN` is unset, passing it to health-monitor and to admin-ui as `ADMIN_UI_HEALTH_MONITOR_TOKEN`. Both compose files bind `0.0.0.0:9203` with `HEALTH_MONITOR_HTTP_TOKEN` **required** (`${HEALTH_MONITOR_HTTP_TOKEN:?…}`, no default) and wire the same value to admin-ui; the dev compose publishes 9203 on `127.0.0.1` only. `cmd/healthreport` (`-token`, default `$HEALTH_MONITOR_HTTP_TOKEN`), `smoke.sh` and the registry smoke send the bearer to `/status`.
- Kubernetes deploy (T-M3-07, NFR-SEC-011): health-monitor binds `0.0.0.0:9203` and gets `HEALTH_MONITOR_HTTP_TOKEN` from a Secret; admin-ui gets `ADMIN_UI_HEALTH_MONITOR_TOKEN` from the same Secret. Helm: new `healthMonitor.token` / `healthMonitor.existingSecret` / `healthMonitor.secretKey` values; rendering fails (`required`) when neither token nor existing Secret is set. Kustomize: base `secretGenerator` from a git-ignored `health-monitor.env` (see `health-monitor.env.example`); no default token in either.

### Added
- Restore drill (T-M2-05, FR-BAK-004, ADR-0013): `scripts/restore-drill.sh --mode host|compose --confirm-wipe` runs the full cycle on fixtures. It brings the stack up with backup-local, runs smoke to seed data, writes a userdata entry, and snapshots `/api/me`, `/api/movies`, `/api/tv`, `/api/requests` and that entry using the original admin password. It then stops everything except core and backup-local, runs `CreateBackup`, and checks archive coverage against the manifest. Then `VerifyBackup{restore_test}`, copy-out and escrow of `backup: false` key material. Next it wipes only the state dirs/volumes, starts a fresh core + backup-local, re-indexes the copied archive, runs `RestoreBackup` into a staging dir, and copies `data/<prefix>/` back by the manifest mapping. Finally it restarts with a decoy bootstrap password and requires the decoy to be refused, the original password to work, an identical snapshot, and a second smoke pass. It prints `PASS: restore drill (N modules restored, snapshot equal)` and refuses to run without `--confirm-wipe`. `--dry-run` prints the mapping. Host mode passes end to end (18 modules restored); compose mode is implemented but not yet exercised. Operator procedure: `docs/RESTORE.md`. Offline tests: `scripts/restore-drill_test.sh`.
- `household-manifest.yaml` `state:` entries gain `host:`, the run-host `data/` directory, used for the host-mode restore mapping. `scripts/lib/state-map.sh` turns the manifest into `id/prefix/location/backup` rows for both modes.
- `cmd/backupctl`: a CLI for backup-local `BackupService` (`create`/`verify`/`restore`/`list`, protojson output). The registry smoke lib has a grpcurl twin (`registry_smoke_cmd_backupctl`) that uses the vendored `proto/muxcore/backup/v1/backup.proto`. The drill test checks that the vendored proto matches backup-local's. The `backup-local` dependency is bumped to v0.1.5 (VerifyBackup).
- Fixture acquisition gate (T-M2-03, FR-INS-003; ADR-0008, ADR-0014): `cmd/acquirefixture` drives the whole path end to end. It ensures TMDB 550 exists in media-movies, calls media-automation `AddToQueue`, runs `SearchItem` (requires at least one match from an indexer named "fixture"; live-indexer matches are never dispatched), and calls `Dispatch` (requires status `sent` and a download id). It then polls `GetHistory` until `completed` (fails fast on `import_failed`/`failed` and prints the detail), checks that media-movies reports `has_file` with the imported file, and checks the BFF: `/api/movies` `stream_url`, a ranged stream GET (200/206), and `/api/playback/resolve`. It has unit tests against an in-process bufconn AutomationService for success, no fixture match, `import_failed`, and timeout.
- `smoke.sh` runs the acquisition step before the scanner ImportPath fixture when a fixture indexer (`indexer-piratebay`) and a downloader (`downloader-native-torrent` / `downloader-qbittorrent`) are registered. `SMOKE_REQUIRE_ACQUISITION=1` makes a missing indexer or downloader a failure. The PASS line names `acquisition` (or `acquisition:skipped`). Registry mode runs the same flow with containerized grpcurl (`scripts/lib/acquisition-smoke.sh`). Offline tests in `scripts/smoke-acquisition_test.sh` cover the gating, JSON parsing, and the registry flow.
- `scripts/check-compose-mountpoints_test.sh`: every non-`/data` named-volume mount point in the registry compose file must be pre-created in the Dockerfile that builds that service.
- `household-manifest.yaml` state model (ADR-0013, FR-BAK-002): a `state:` map listing each stateful module's volume, mount, env, kind, `personal`, and optional `backup: false`/`shares`/`service`; a `stateless:` list; and `excluded_volumes:` with reasons (library media, key material, backup output).
- `scripts/check-state-coverage.sh` (+ `_test.sh` with good/bad fixtures under `scripts/testdata/state-coverage/`, run by `run-script-tests.sh`). It checks that every required or recommended module is in `state` or `stateless`, and that each state entry's volume, mount, and env match its registry compose service. It also checks that backup-local mounts every backed-up volume read-only at `/source/<module-id>` and lists it in the default `BACKUP_SOURCE_DIRS`, and that excluded volumes are never archived. Drift in optional modules only produces a warning. Requires mikefarah `yq` v4 and `jq`.
- `scripts/check-publish-set.sh` (+ `_test.sh`, run by `run-script-tests.sh`): fails when any image in `docker-compose.registry.yml` (all profiles) is missing from `publish-module-images.sh` `DEFAULT_MODULES` (T-M2-02, TDD section 5). `muxcored` (module `core`) is published by `publish-muxcored-local.sh`.
- `cmd/mediauiprox/routes_inventory_test.go` and a complete `BFF-API.md` "Route inventory" table: the test fails on any registered route missing from the doc or documented but not registered (T-M2-08, TDD section 7).

### Fixed
- `run-host.sh` userdata-local now gets `USERDATA_LOCAL_DB_PATH=data/userdata/userdata.db`. The module ignored the `USERDATA_LOCAL_DATA_DIR` it was given and wrote to `~/.muxcore/userdata.db`, outside `data/` and outside every backup. Upgrade note: run-host warns when the old file exists; move `~/.muxcore/userdata.db*` into `data/userdata/` to keep existing progress and favorites.
- `run-host.sh stop` (and `up`, which stops first) now waits up to `MVP_STOP_TIMEOUT_SEC` (15) for processes to exit and then SIGKILLs any still running. Before, it returned while they were still shutting down: a slow or hung `muxcored` kept :9090/:8080, the next core failed to bind, and the mesh was left without a core. The orphan sweep also matches binaries by path, because `pkill -x` misses names longer than 15 characters.
- `cmd/acquirefixture` accepts a library file whose name has the release tokens, ignoring case and punctuation (`Fight Club (1999) [720p.WEB-DL].mkv` for `Fight.Club.1999.720p.WEB-DL`). A re-run on a library that already holds the release (smoke after a restore) re-imports into the same file id, and the raw substring check used to time out.
- `mediauiprox` `reverseProxy` set both `Director` (via `NewSingleHostReverseProxy`) and `Rewrite`, so every proxied `/stream/movies/`, `/stream/tv/` and image request returned 502. Regression test added.
- `smoke.sh` called the shell function `smoke_cmd_listmodules` through `env`, which cannot run functions, so host-mode smoke failed at discovery. The required-module list no longer includes the optional `jellyfin` bridge (off by default). The script now also accepts auth-local's renamed CSRF cookie `muxcore-auth-csrf`, and accepts `/api/jellyfin/play` 503 when the bridge is not enabled.
- `mediauiprox` panicked at startup on two `net/http` ServeMux pattern conflicts: `/api/tv/login` (now `POST /api/tv/login`) vs `PATCH /api/tv/{id}`, and `GET /api/music/tracks/` (now `GET /api/music/tracks/{id}/lyrics`) vs `GET /api/music/{id}/history`.
